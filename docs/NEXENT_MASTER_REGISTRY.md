# NEXENT Master Registry

The master registry turns the planned index hierarchy into an executable data structure.

It is an indexing/provenance boundary, not a proof engine. Registration never upgrades evidence status.

## Index families

The registry vocabulary covers master entities, systems, subsystems, mechanisms, formulas, algorithms, languages, syntax, semantics, AST, IR, runtime, kernel, events, state, contracts, capabilities, authority, governance, evidence, verification, proof, memory, simulation, genome, generation, evolution, projects, repositories, libraries, files, visual artifacts, dependencies, lineage, legacy-to-canonical, canonical-to-implementation, implementation-to-proof, and proof-to-evidence.

## Evidence rule

`RESTORED != CANONICAL != IMPLEMENTED != TESTED != VERIFIED`.

Recovered archive material must retain provenance and must not be silently promoted.

## Integration boundary

The next ingestion stage can populate this registry from actual repository history and archived artifacts, preserving source, first appearance, aliases, dependencies, and evidence before reconciliation.
