# NEXENT — MASTER ENGINEERING WORK

This document freezes the current engineering reference boundary. It is not a claim that every historical concept has been recovered or experimentally verified.

## A. Reconstruction
Archive Reconstruction Fabric classifies source material as RESTORED, CANONICAL, DERIVED, PROPOSED, CONFLICT, or DUPLICATE. Deduplication is conservative and content-based.

Pipeline:
Raw Material -> Extraction -> Normalization -> Deduplication -> Lineage -> Canonical Candidate.

## B. Unified model
Reality -> Problem -> Requirements -> Meaning -> Ontology -> Contracts -> Capabilities -> Architecture -> Languages -> AST -> IR -> Binding -> Execution -> Events -> State -> Evidence -> Proof -> Governance -> Operation -> Learning -> Evolution.

One canonical model may produce many representations, but each representation retains provenance.

## C. System Genome
G(S) = {Identity, Purpose, Behavior, Capabilities, Dependencies, Constraints, Evidence, History}.

The software implementation exposes this as SystemGenome. The term genome is an engineering metaphor for a structured system identity; no biological claim is implied.

## D. Nexus
Nexus is a relation fabric with semantic, dependency, capability, contract, evidence, causal, execution, provenance, evolution, and architecture layers.

Impact traversal is graph reachability. It is not automatically causal inference.

## E. System algebra
compose, decompose, refine, substitute, and diff are deterministic structural operations. Their complete algebraic laws remain formalization targets until separately proven.

## F. Native language family
The current NXL registry defines:
NXL-S, NXL-SYS, NXL-ARCH, NXL-CON, NXL-PROOF, NXL-EXEC, NXL-EVO, NXL-Q, NXL-VIS.

All nine are PROPOSED at this implementation stage. Python/Rust/etc. remain host implementation substrates; they are not silently treated as the semantic source of truth.

Required language specification:
Purpose -> Syntax -> Semantics -> Types -> State -> Events -> Contracts -> Compiler -> IR -> Runtime Binding -> Verification -> Boundaries -> Differences -> Examples.

## G. UIR
NEXENTUIR is the canonical intermediate representation boundary. It binds semantic data, genome, contracts, capabilities, relations, and proof obligations and exposes a deterministic fingerprint.

## H. Proof and evidence
Claim -> Property -> Proof Obligation -> Method -> Result -> Evidence -> Verification.

Generated != Verified.
Test passed != Mathematical proof.
Simulation result != Physical evidence.

## I. Visual derivation
Diagram = Render(Canonical Model).

Visual artifacts must identify the model/version they represent. A drawing is representation, not proof.

## J. Runtime and authority
Execution remains subject to explicit authorization where the operation requires it. Authority is separate from intelligence. Persistent ledger support is now available through the kernel ledger path.

## K. Evolution
Observe -> Model -> Diagnose -> Generate Alternatives -> Simulate -> Compare Constraints -> Verify -> Prove -> Govern -> Deploy -> Observe Again.

Promotion is a governed state transition, not an automatic consequence of generation.

## L. Innovation lineage
Historical VX/VAIXLNS and other material is provenance-separated. It can be RESTORED or DERIVED into NEXENT only through explicit mapping. Names alone do not make an old concept NEXENT-canonical.

## M. Verification boundary

- conservative archive classification
