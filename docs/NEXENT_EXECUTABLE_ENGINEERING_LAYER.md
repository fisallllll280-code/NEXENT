# NEXENT Executable Engineering Layer

Runtime transformation: Intent -> SystemContract -> Artifact/Evidence -> ExecutionPlan -> Authorization -> Handler -> Result.

A system contract receives a deterministic canonical identity. Artifacts carry claims, assumptions, evidence, provenance, and verification status. A plan becomes executable only when an implementation handler exists and a tested, verified, or approved proof-carrying artifact exists.

Boundary rules: a drawing is representation, not proof; a simulation is a model, not physical reality; a model is not an implementation; intelligence does not grant authority; execution requires explicit authorization; missing evidence blocks execution.

Implemented here: canonical contracts, proof-carrying artifacts, deterministic execution planning, bounded handlers, input validation, explicit authorization, and tests for the execution boundary. Persistent ledger integration, automatic multi-mind coordination, formal theorem proving, hardware actuation, frontend generation, and production verification remain separate target work.
