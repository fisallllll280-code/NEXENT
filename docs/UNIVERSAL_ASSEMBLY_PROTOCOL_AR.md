# بروتوكول التجميع الشامل NEXENT

## الهدف
هذه الطبقة لا تستبدل المشاريع ولا تحذف أفكاراً. هي تجمع **المرجعيات، الملفات، التشغيلات، المقارنات، الأدلة، والقرارات** في سجل قابل للتتبع.

## قاعدة عدم الضياع
كل عنصر يدخل أحد الحالات:
- PRESERVED: محفوظ كما هو.
- IMPLEMENTED: له تنفيذ قابل للتشغيل.
- TESTED: اجتاز اختباراً.
- VERIFIED: لديه دليل تحقق.
- CANDIDATE: فكرة/اقتراح يحتاج تحققاً.
- CONFLICT: توجد نسخ أو تعارضات ويجب إبقاؤها حتى الحسم.
- BLOCKED: معروف لكن التشغيل متعذر حالياً.
- EXCLUDED: مستبعد فقط بقرار موثق، وليس محذوفاً.

لا يتم حذف الأصل لمجرد وجود نسخة أفضل؛ النسخة الأفضل ترتبط بالأصل عبر provenance.

## دورة العمل
1. Inventory: حصر المستودعات والملفات.
2. Snapshot: تثبيت commit المرجعي لكل مستودع.
3. Provenance: ربط كل ملف/فكرة بمصدرها.
4. Compare: مقارنة البنى والواجهات والاختبارات والتشغيل.
5. Synthesis: استخراج التقاطعات والتعارضات والقدرات الفريدة.
6. Selection: اقتراح تحسينات وفق معايير موثقة، بدون إسقاط البدائل.
7. Build: تنفيذ التغييرات في فرع مستقل.
8. Test/Run: تشغيل الاختبارات والـ smoke والـ replay حيث يتاح.
9. Evidence: حفظ نتائج التشغيل والـ hashes والـ commits.
10. Publish: نشر الصفحة ونتائج الحالة عبر GitHub.

## المقارنة
المقارنة ليست «اختياراً سريعاً». لكل فكرة نسجل:
- المصدر
- الوظيفة
- درجة التنفيذ الحالية
- الاختبارات
- التداخل
- الاعتماديات
- قابلية الدمج
- المخاطر
- الدليل
- البدائل التي بقيت محفوظة

ثم يمكن إنشاء توصية هندسية قابلة للمراجعة دون فقد أي خيار.

## حدود التشغيل
المواصفات والوثائق لا تُعامل كأنها برامج قابلة للتشغيل. النظام يميز صراحة بين SPECIFIED وIMPLEMENTED وTESTED وVERIFIED وBLOCKED.
