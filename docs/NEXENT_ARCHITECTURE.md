# NEXENT Architecture — v0.1

NEXENT is an organizing runtime: it turns a system description into registered structure, governed intent, execution, evidence and controlled evolution.

## Composite innovations

1. System Graph — typed entities + dependency validation.
2. Constitutional Gate — policy is outside the intelligence path; execution cannot bypass it.
3. V-IR inspired semantic boundary — Intent is lowered into a stable intermediate representation.
4. Proof Lease — capability authorization can be time-bounded and scope-bound.
5. Hash-chain Ledger — transitions become auditable events.
6. Evidence Binding — output is linked to input/output hashes, policy and ledger head.
7. Replay Boundary — ledger integrity is independently checkable.
8. Controlled Evolution — proposals are separate from deployment and require explicit approval.
9. NEXENT DSL — a human-readable intent surface.
10. Capability Registry — capabilities are versioned resources.

## Execution fabric

INTENT -> DSL/Adapter -> V-IR -> Constitutional Gate -> Capability Resolution -> Proof Lease -> Execution -> Event Ledger -> Evidence -> Replay/Verification -> Evolution Proposal

## Truth boundary

NEXENT distinguishes specification, runtime result, evidence and verification.

## Explicit non-claims

Distributed consensus, persistent databases, cryptographic signatures, sandbox isolation, full knowledge graph, multi-agent mesh, external connector execution and production deployment remain future layers until implemented and tested.
