# NEXENT Intent Web — Implementation v1\n\n## Purpose\n\nNEXENT Intent Web is the first executable implementation of the new web model:\n\n**Intent -> Context -> World -> Objects -> Governed Actions -> Evidence -> Memory -> Evolution**\n\nIt is not a normal web page and it is not an LLM wrapper. The web client is a presentation layer over the existing NEXENT governed kernel.\n\n## Implemented components\n\n- **Intent Internet**: `POST /api/intent` creates a deterministic intent identity and a world.\n- **Web World**: `WebWorld` is a task-scoped state container.\n- **Web Object Model**: `WebObject` represents semantic/stateful objects with capabilities and provenance.\n- **Intent Continuity**: context is attached to the world and preserved in its metadata.\n- **Executable Web**: `WebAction` maps an explicit UI action to a governed capability.\n- **Evidence Web**: every governed action goes through `NexentKernel.execute`, creating ledger events and evidence.\n- **World Memory**: structured memory entries are stored inside the active world.\n- **Generative Interface**: the UI renders its workspace from the current world's objects, relations, memory, and actions.\n- **Web Evolution surface**: the event fabric is queryable and exposes the lifecycle of the world.\n- **Governed Intelligence Surface**: an AI adapter boundary exists, but model output cannot bypass NEXENT governance.\n\n## Runtime\n\n```text\nBrowser / PWA\n     |\n     v\nNEXENTWebServer\n     |\n     v\nWebRuntime\n     |\n     +--> Intent compiler / world builder\n     +--> Web Object Model\n     +--> Web Action capability boundary\n     |\n     v\nNexentKernel\n     |\n     +--> Constitution\n     +--> EventLedger\n     +--> ProofEngine\n     +--> Evidence\n     |\n     v\nReplay / verification boundary\n```\n\n## API\n\n### `GET /api/health`\n\nReturns a basic liveness response.\n\n### `GET /api/status`\n\nReturns runtime, ledger, world, intent, innovation, and AI-adapter status.\n\n### `POST /api/intent`\n\nExample:\n\n```json\n{\n  "objective": "Build a research workspace",\n  "actor": "WEB_USER",\n  "context": {\n    "domain": "science",\n    "depth": "deep"\n  }\n}\n```\n\n### `GET /api/world/{world_id}`\n\nReturns the full semantic world, including objects, relations, actions, memory, and metadata.\n\n### `POST /api/world/{world_id}/action/{action_id}`\n\nExecutes a declared action through the kernel governance boundary.\n\n### `GET /api/events?since=0`\n\nReturns ledger events after the requested sequence number.\n\n### `GET /api/innovations`\n\nReturns the web innovation catalog and implementation bindings.\n\n## Run\n\n```bash\npython -m nexent.cli web --host 127.0.0.1 --port 8787\n```\n\nOpen:\n\n```text\nhttp://127.0.0.1:8787/\n```\n\nThe web client is a PWA and uses no frontend framework or external runtime dependency.\n\n## AI boundary\n\nAn AI provider can implement:\n\n```python\nclass Adapter:\n    def plan(self, context):\n        ...\n```\n\nand be registered with:\n\n```python\nruntime.register_ai_adapter(adapter)\n```\n\nThe adapter is intentionally advisory. The kernel remains authoritative for capability execution, governance, events, evidence, and proof.\n\n## Current verification level\n\n**IMPLEMENTED_FOUNDATION**\n\nThe repository now contains executable web code and HTTP integration tests. This does **not** claim a production-grade external AI model, authentication provider, multi-user distributed state, TLS termination, or autonomous internet-wide agent execution. Those are separate adapters and deployment layers.\n\n## GitHub verification\n\nCI must run:\n\n```bash\npython -m pytest -q\npython -m nexent.cli status\npython -m nexent.cli demo\n```\n\nThe web implementation is considered operational only after GitHub Actions reports these checks as successful.
