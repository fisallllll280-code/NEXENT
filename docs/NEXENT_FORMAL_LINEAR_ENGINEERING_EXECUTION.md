# NEXENT — Complete Linear Engineering Execution Contract

This is the repository execution contract.

REQUIREMENTS -> MODEL -> ARCHITECTURE -> CONTRACTS -> IR -> IMPLEMENTATION -> VERIFICATION -> VALIDATION -> EVIDENCE -> GOVERNANCE -> RELEASE -> OPERATION -> EVOLUTION

Every phase produces an identifiable artifact, verification evidence, and traceability to its predecessor. No phase is silently skipped.

An artifact identity is based on artifact id, phase, kind, and a canonical content digest. The digest is an integrity identifier, not proof of semantic correctness.

The repository is organized as a set of distinct engineering layers:

FOUNDATION: canonical identity, laws, invariants, terminology.
KNOWLEDGE: observation, evidence, provenance, memory.
DISCOVERY: capability voids, missing-system discovery, impossibility decomposition, hypotheses.
REASONING: differentiated specialist assessments, adversarial challenge, counterexamples, counterfactuals.
SYNTHESIS: system genome, architecture search, dependency graph, candidate generation.
FORMAL ENGINEERING: contracts, IR, proof obligations, verification, validation, simulation.
FORGE: deterministic compilation, generation, packaging, system twin.
GOVERNANCE: authority, safety constraints, approval, change control.
RUNTIME: execution, ledger, replay, monitoring, containment.
EVOLUTION: self-audit, capability discovery, hypothesis, verification, governed promotion.

Evidence is not allowed to replace engineering truth.

GENERATED != VERIFIED
TESTED != PROVEN
SIMULATED != VALIDATED
INTEGRITY != CORRECTNESS

Completion means more than source files existing. A release requires canonical artifacts, closed gates, passing tests, verification evidence, validation scenarios, verified evidence integrity, recorded governance approval, reproducible release generation, and runtime observation.

ISO/IEC/IEEE 15288:2023 provides a common systems life-cycle process framework across systems and systems of systems; ISO/IEC/IEEE 29148:2018 defines requirements-engineering processes and traceability concepts.
